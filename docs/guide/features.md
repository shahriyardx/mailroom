# Features

**Settings → Features.**

Two products share this app, and an instance says which of them it is:

| | |
| --- | --- |
| **Inbox** | Mailboxes, conversations, filters, labels, forwarding, the browser extension |
| **Campaigns** | Lists, broadcasts, unsubscribe handling |

**Both can be on.** A company with team mailboxes and a newsletter needs one
instance, not two.

Switching one off hides its screens. Nothing is deleted, so switching it back
on finds everything where you left it. One of the two has to stay on — an
instance with neither would have navigation with no way back to this page.

Each is a view of its own with its own sidebar. With both on, a switcher at
the top of the sidebar moves between them; with one on, there is no switcher,
because there is nowhere to switch to.

Settings is shared. Domains, templates, the email log and delivery reporting
are read by a marketing instance as much as by a mailbox one, so they stay
visible whatever you choose.

## First run

A fresh instance asks three questions before handing you anything: what it is
for, what it is called, and what is left to do.

The last of those is a live checklist, not a stored list of ticks. An item that
stops being true goes back to undone, and leaving halfway loses nothing —
every item links to the real screen for that job.

You can finish with items outstanding. Waiting on DNS is not a reason to be
held on a setup screen.
